# Admin fishing

Render > Admin > Paramètres > Déplacement selects Auto tapis, Auto pêche, or no idle activity. AutoFishing defaults false; it cannot be saved together with AutoTreadmill=true. Reload Loaders/Admin.lua to install the updated runtime.

AdminFishing uses the existing game rod controller (Tool Activate/Deactivate) and FishingUI; it creates no GUI and does not fabricate a caught result. Each cast resolves a rod again, equips it through Humanoid, and confirms its parent and Fishing.EquippedRod before activation. The release reads the existing Charge.Tag position normalized through the Track WindowTop/WindowBottom attributes, and waits for the live PerfectMin/PerfectMax midpoint. The native IsPerfect confirms it. ChargeSeconds bounds the wait; no fixed 1000 ms release is used. A missing gauge cancels instead of falling back to a timer. It only clicks when the native Reel panel is visible, at no more than 12 clicks/s or the live lower limit.

The fixed site is Workspace.World.Build.AlienBiomeZone.Zone14Props.Dock, facing Workspace.World.Build.AlienBiomeZone.LagoonFerry.Course. The largest horizontal deck surface defines a point inset four studs from the edge toward Course; arrival checks horizontal and vertical distance. Course is a direction marker: the native charge still controls cast distance. The actual water endpoint is verified with Fishing.Probe. No arbitrary bank fallback is used. Missing access, speed, rod, bank, or UI confirmation produces a status and ten-second backoff. It does not unlock the ferry or bypass access checks. Routes and casting remain to be verified in a live session; Studio tests use mocks.

AUTO OFF, eligible queued egg, remote teleport, manual action, character change, or option change aborts fishing. Cancellation unequips the owned rod before Deactivate, so a charging cancellation cannot release another cast; camera framing is restored. Existing flight arrival and maintenance priorities are preserved.

Validation: AdminFishing, AdminMutations, AdminArrival, AdminMaintenance Studio mocks; full Hub compilation; Render settings and dashboard selector tests. No live cast was executed by these tests.

## Native remotes inspected

Shared.Remotes declares Fishing.Hold (event), Cast (function), Reel (function), Cancel (event), AskClaimMastery (function). FishingController sends Hold with no arguments; Cast receives actual hold duration and the validated water point. Its response includes Id, Wait and Mode. The native controller waits before entering Reeling; it reports Reel(Id, "Caught", actualClicks) only after its meter fills. The controller reveals a reward only when the server returns true and a reward table. Admin continues to use this native controller, without duplicate remote calls or hooks. It waits for native Reveal or an increase in replicated FishingMastery.Caught before displaying a confirmed capture. The pre-bite timeout includes the controller's ten-second server-response allowance, flight time and live bite delay.

AlienLagoon.Request/Arrive/Leave/Travel handle boat travel, and Trade exchanges Void Pearls. They are not fishing casts and Admin does not invoke them. The native FerryMarker helper resolves Course; inside-lagoon state and Scriptable camera transitions block/interupt dock fishing.
